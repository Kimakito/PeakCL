# Politique : tout est ouvert, recherche comme entrainement. Le contenu du site
# est deja public et l'objectif est la visibilite, y compris dans les reponses
# generees par les assistants IA.
#
# ATTENTION en modifiant ce fichier : un groupe `User-agent:` nomme REMPLACE le
# groupe `*`, il ne s'y ajoute pas (regle du groupe le plus specifique). Un
# groupe nomme qui doit bloquer /cadrage/ doit donc repeter son `Disallow`,
# sinon les decks clients deviennent crawlables par ce bot precis. C'est la
# raison d'etre de la repetition plus bas, qui a l'air redondante mais ne
# l'est pas.
#
# /cadrage/ (decks clients) n'est PLUS bloque pour les moteurs de recherche.
# Un Disallow n'empeche pas l'indexation : il empeche la LECTURE de la page.
# Google indexait donc l'URL sans jamais voir le
# `<meta name="robots" content="noindex, nofollow">` que ces pages servent
# deja en SSR — d'ou le « indexee malgre le blocage par robots.txt » de
# Search Console. Le crawl est ouvert pour que ce noindex soit enfin lu et
# applique. Un `X-Robots-Tag: noindex, nofollow` sur /cadrage/* dans
# netlify.toml double la protection.
# Les bots d'ENTRAINEMENT gardent le Disallow : eux n'obeissent qu'a
# robots.txt et ignorent le meta noindex.
# Ne pas remettre de `Disallow: /cadrage/` sur les groupes moteurs : cela
# recreerait exactement le bug.

User-agent: *
Allow: /
